Code and API costs

Pinned-runtime costImplementation
Wasm importsTyped host calls include argument packing, dispatch and result copying. The import timer also covers direct CUS ticks outside the dispatch timer; these scopes overlap and cannot be subtracted.
Fire uploadsBoth upload particle births and evaluate curves on the GPU. The Lua VBO API extracts each table number into a temporary vector. Rust supplies contiguous f32 data to the native VBO API. Both then pack attributes into native shadow buffers before OpenGL upload. Upload batching and lifetime retention still require alignment before attributing the measured gap to this API conversion.
JobsThe pinned jobs implementation creates private stores and copies inputs/outputs. Light/weight kernels are measured off/on at widths 1 and 4. GPU fire has no CPU curve work to parallelize; its separate jobs comparison updates particle curves on the CPU and still draws through NVIDIA OpenGL.
Shared engine workNative movement, pathfinding, model submission and GPU synchronization run in both versions. HAPFS dispatches path requests over this same pool. Repeated identical Lua runs already show path-state variation at width 4; width 1 is the primary control.

Reproduce and audit

Method and source data

Timings

Target: five clean alternating pairs; 300 warmup + 600 measured steps; one draw per step; 1024×736; VSync/sound off. A failure or CPU/GPU overlap excludes both members. Rejected attempts remain visible.

World recordings

Fresh runs with a read-only observer, derived from Ship Game’s recording approach. All observed units and sampled projectiles are retained. They show workload and movement; serialization makes them unsuitable timing baselines.

CPU sampling

Fresh runs without the world observer. Linux perf samples user CPU at 499 Hz with DWARF stacks and JIT names. Sampling perturbs execution; stack proportions diagnose hot paths, rather than replace paired timings.

Each comparison uses the same engine binary for both versions; its commit and SHA-256 are shown in the scene lab. Release 2026.10.25 and separately tested API corrections retain their own identities. NVIDIA hardware rendering is required; the existing runner rejects llvmpipe and other software renderers. The current runner waits for ten quiet seconds before timings, profiles and recordings. The CPU guard checks global and selected-scope pressure; the GPU guard monitors competing GPU processes. Activity interrupts new captures and excludes their pair. Earlier diagnostic worlds/videos are retained outside timing aggregates. All engine threads are pinned to the eight P cores; E cores are excluded.
