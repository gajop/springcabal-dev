Method and source data

Timings

Target: five clean alternating pairs; 300 warmup + 600 measured steps; one draw per step; 1024×736; VSync/sound off. A failure or CPU/GPU overlap excludes both members. Rejected attempts remain visible.

World recordings

Fresh runs with a read-only observer, derived from Ship Game’s recording approach. All observed units and sampled projectiles are retained. They show workload and movement; serialization makes them unsuitable timing baselines.

CPU sampling

Fresh runs without the world observer. Linux perf samples user CPU at 499 Hz with DWARF stacks and JIT names. Sampling perturbs execution; stack proportions diagnose hot paths, rather than replace paired timings.

Each comparison uses the same engine binary for both versions; its commit and SHA-256 are shown in the scene lab. Release 2026.10.25 and separately tested API corrections retain their own identities. NVIDIA hardware rendering is required; the existing runner rejects llvmpipe and other software renderers. The current runner waits for ten quiet seconds before timings, profiles and recordings. The CPU guard checks global and selected-scope pressure. New captures also limit background CPU use to 0.5 logical cores, excluding the runner and its children; the scene runtime shows whether this guard was used. The GPU guard monitors competing GPU processes. CPU activity is checked through the first sample after the final frame marker, including its straddling interval; later shutdown activity stays recorded. Missing markers retain the full-process guard. GPU and CPU-pressure checks still cover the whole process. Activity inside the guarded interval excludes both pair members. Boundary tests and live CPU-contention check. Earlier diagnostic worlds/videos are retained outside timing aggregates. All engine threads are pinned to the eight P cores; E cores are excluded.
